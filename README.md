# UNC Toilet

校园厕所实时评测应用。目标是在用户需要如厕的几秒内，回答三个问题：哪里有厕所、现在是否值得去、如何最快到达。

## 项目状态

- 阶段：产品与技术方案起草，尚未进入代码开发。
- 当前交付：已建立产品目标、第一性原理、架构边界和 Agent 协作规范。
- 当前项目目录：`14-UNC Toilet`。
- 核心原则：简洁、高效、上手快；优先提供可行动的信息，不堆叠功能。
- 运行范围：校园内所有已登记厕所；默认监测时段为每日 07:30 至次日 00:00。

## 核心体验

1. 打开应用后优先看到附近厕所及其当前状态。
2. 用户用极少操作完成环境评价。
3. “有屎没冲”等影响他人使用的异常可以被快速上报，并有明确的失效和关闭机制。
4. 用户可以直接导航到附近的高评分厕所。
5. 排行榜分为“累计评分榜”和“当日实时评分榜”，分别服务长期稳定性判断和即时选择。
6. 交互借鉴 Dating App 的直观、快速反馈感，但不采用滑动作为主要交互：评价应依靠清晰按钮、状态确认和低认知负担完成。

## 当前待决策事项

- 评分是二级（好/差）、三级（差/一般/好）还是四级；默认优先验证三级。
- 是否允许匿名评价；默认不公开用户身份，服务端保留最小反滥用凭据。
- “有屎没冲”是否为唯一紧急异常，还是包含“无纸”“无水”“堵塞”“无法进入”等类别。
- 实时评分的有效窗口、时间衰减和最低样本数。
- 异常警报的展示范围、默认持续时间、确认机制和通知对象。
- 厕所开放时段是否按校园建筑/楼宇分别配置。
- 是否需要管理员维护厕所目录和处理异常。

## 验收指标草案

- 首屏能在不阅读说明的情况下识别附近厕所、当前评分和更新时间。
- 从打开应用到开始导航不超过 3 次关键操作（首次授权除外）。
- 评分提交不超过 2 个明确动作，并能看到提交结果。
- 过期或低可信度数据不会被展示成确定事实。
- 关键流程在定位失败、网络慢、无数据、厕所关闭、异常冲突时仍有可理解的反馈。
- 首次试运行收集的指标和用户反馈可追溯到版本与规则变更。
